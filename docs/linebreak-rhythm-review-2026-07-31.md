## 1. `overflow-wrap: break-word`가 `keep-all`을 덮었다 ✅

```css
word-break: keep-all;        /* 단어 중간에서 끊지 마라 */
overflow-wrap: break-word;   /* 넘치면 아무 데서나 끊어라 ← 넘침 상황에서 이김 */
```

컨테이너가 1px만 좁아져도 `keep-all`이 무효가 되어 숫자·영문 토큰 중간이 갈렸다.
`overflow-wrap: normal`로 바꾸고, 넘침 처리가 실제로 필요한 곳에만 국소 적용했다.

- `ContactCard`의 이메일 → `break-words` (좁은 폭에서 실제로 넘칠 수 있는 유일한 토큰)
- 케이스 본문에는 인라인 코드·경로가 없어 추가 대상 없음

**전역 fallback 제거와 지표 폭 확보는 함께 배포해야 한다** — 1만 적용하면 좁은 열의 값이
넘쳐 구분선을 침범한다. 같은 커밋으로 처리했다.

## 2. 지표 값을 원자 단위로 고정 ✅

`whitespace-nowrap`을 **값에만** 추가했다(라벨은 감싸도 된다).

| 파일 | 대상 |
|---|---|
| `CaseStudyCard.tsx` | `text-xl ... tabular-nums` |
| `Hero.tsx` | `text-4xl` 주 지표 |
| `ResumeExperience.tsx` | `MetricsBlock` 값 |
| `projects/page.tsx` | 헤드라인 카드 값 |

지표 열 폭도 `w-20`(80px) → `w-28`(112px). 실측 근거:

```
headline value 최장 = "58→90%" / "MCP 4종"
text-xl(20px) tabular 숫자 advance = 1258/2048em ≈ 12.3px
"58→90%" ≈ 82px < 96px (112 − pr-4 16px)
```

`projects/page.tsx`는 이미 `w-24 sm:w-28`이라 폭 변경 불필요 — `nowrap`만 추가했다.

## 3. 지표 슬롯 계약 복원 ✅

```
value = 짧은 수치 토큰 (−70%, 62%, 0→1, 3.2×)  — text-xl, 원자 단위
label = 무엇에 대한 수치인가                    — text-xs, 감싸도 됨
```

`MetricsBlock`이 `flex items-baseline`이라 한 셀이 2줄이 되면 행 전체 높이가 밀린다.
"옆 문구 높이가 바뀐다"의 정체가 이것이었다.

```diff
- value: "견적 시간 −70%"   label: "12 필드 → 3 카테고리"
+ value: "−70%"             label: "견적 시간 · 12→3 필드"
```

### ⚠️ 카트 조회 건 — 제안된 병합은 사실 오류라 채택하지 않았다

리뷰는 `caseStudies.ts:169`의 `−70% API 호출`이 같은 건이면 그 수치를 value로 올리라고
했다. **다른 건이다.**

| | 카트 조회 | −70% API 호출 |
|---|---|---|
| 회사 | 티오더 | 라이트하우스 |
| 내용 | `get_cart_list` 자기증식 요청 루프 규명 | 데일리북 Redux Saga → React Query 마이그레이션 |
| 출처 | `resume.ts:96` | `resume.ts:258`, `caseStudies.ts:164` |

수치를 빌려오면 이력서에 없는 성과가 생긴다. 서술 압축만 했다.

```diff
- value: "카트 조회 급증 해소"   label: "원인 규명 → 개선 배포 완료"
+ value: "급증 해소"             label: "카트 조회 · 원인 규명 후 배포"
```

수치가 없어 지표 슬롯에 완전히 맞지는 않는다. 티오더 지표 3칸 중 유일하게 완결된
항목이라 남겨 두지만, 대체할 수치가 생기면 교체 대상이다.

## 4. NBSP ✅

`keep-all`은 **공백에서의 줄바꿈을 막지 않는다.** 의미 단위를 붙이려면 NBSP가 필요하다.

| 파일 | 변경 |
|---|---|
| `resume.ts:58` | `v1.5.x 운영 중` |
| `caseStudies.ts:43` | 동일 |
| `QuoteTimeSimplification.tsx:37` | `12 필드 → 3 카테고리` |

**반드시 ` ` 리터럴 이스케이프로 쓴다.** 소스에 보이지 않는 NBSP 문자를 넣으면
다음 사람이 일반 공백으로 되돌려 놓는다.

> 작업 중 `resume.ts:58`에 **이미 raw NBSP 문자가 들어가 있는 것**을 발견해 이스케이프로
> 교체했다. 저장소 전체 재검사 결과 raw NBSP 0건.
>
> 검사에 `grep -P`를 쓰면 안 된다 — macOS BSD grep은 `-P`를 지원하지 않아 **조용히 실패**하고
> `|| echo "0건"` 뒤에 숨는다. 파이썬으로 확인할 것.

## 5. Skills `h-full` 체인 ✅

`ScrollReveal`은 그리드 아이템이라 stretch되지만 내부 카드에 `h-full`이 없어 태그 개수만큼
높이가 달라졌다. `ScrollReveal className="h-full"` + 카드 `flex h-full flex-col`로 체인을 이었다.
`ScrollReveal`은 이미 `className`을 받으므로 컴포넌트 수정 불필요.

## 6. `--header-h` 상수 ✅

`ResumeToc`가 `sticky top-16`(64px)인데 헤더 실제 높이는 52px이라 12px 틈으로 본문이 비쳤다.
헤더 높이는 터치 타깃 작업에서 50 → 52px로 드리프트한 값이라 하드코딩을 반복하면 또 어긋난다.

```css
--header-h: 52px;
```

**핵심은 헤더에 `h-[var(--header-h)]`를 걸어 변수가 실제 높이를 강제하게 하는 것이다.**
변수만 선언하고 헤더를 패딩으로 두면 둘이 다시 갈린다.

헤더를 `flex items-center`로 바꾸면서 `nav`에 `w-full`을 추가했다 — 안 그러면 `nav`가
flex 아이템이 되어 콘텐츠 폭으로 줄고 `justify-between`이 무너진다.

배경도 `bg-zinc-50/90` → `/95`. 두 스티키 레이어가 맞붙으면 투명도 차가 경계선으로 드러난다.

`scroll-mt-28`(112px)은 헤더 52 + ToC 약 40 = 92px을 덮으므로 적정. 헤더 높이를 바꾸면
이 값도 함께 봐야 한다.

## 7. 문구 — `프론트엔드는 저 혼자` ✅

```diff
- ko: "정규직 | 개발 3명 (CTO, AI, 프론트엔드는 저 혼자) / 전체 5명 (+ PO, PD)"
+ ko: "정규직 | 개발 3명 (CTO · AI · 프론트엔드) — 프론트엔드 단독 / 전체 5명 (+ PO, PD)"
```

"혼자"는 겸양으로, "단독"은 범위로 읽힌다. 1인 담당은 축소할 사실이 아니라 책임 범위를
말하는 사실이다. 메타 줄의 나머지가 전부 명사구라 톤도 맞는다.

> 리뷰의 근거 중 "영문판에는 이 표현이 없어 두 언어의 정보량이 다르다"는 **사실과 다르다.**
> `resume.ts:130`에 `and me as the only frontend`가 있었다. 다만 같은 톤 문제가 영문에도
> 있어 함께 고쳤다(`sole frontend engineer`).

## 8. 행간 · 최소 크기 ✅ (일부 보류)

`CaseStudyCard`의 지표 라벨 `text-xs leading-snug` → **`text-sm leading-relaxed`**.
한글은 받침 때문에 상하 여백이 좁아 1.6 미만에서 줄이 붙어 보인다.

한 줄로 끝나는 값(`text-xl`)은 `leading-tight` 유지 — 감싸지 않는 텍스트에 행간은 관여하지
않고, 지표는 붙어 있어야 덩어리로 읽힌다.

### `text-[13px]`을 거쳐 `text-sm`으로 정정

처음에는 리뷰안대로 `text-[13px]`을 넣었다가 걷어냈다. **13px을 토큰으로 등록하는 것도
답이 아니다** — `visual-review` 4-1이 `text-[11px]`을 걷어낸 이유가 "스케일이 닫혀
있어야 한다"였는데, 13px을 등록하면 이미 많다고 본 7단계를 8단계로 늘리는 것이라
방향이 반대다.

`text-sm`(14px)이면 된다. 4-2에서 14px을 문제 삼은 건 **부제목** 역할에서 16px 본문과
위계가 안 난다는 것이었다. 지금 대상은 지표 라벨이라 **대비 상대가 본문이 아니라 위의
값(`text-xl` 20px)이다.** 20 대 14면 충분히 갈린다. 역할이 다르므로 같은 결론을 적용할
이유가 없다.

12px은 태그 배지처럼 한두 단어 토큰에만 남긴다. **스케일 7단계 유지, 텍스트 임의값 0건.**

> 남은 `text-[10px]` 4건은 `ProjectVisual`의 장식 화살표(`▶◀↘↗`)다. 글자가 아니라
> 아이콘이라 타입 스케일 대상이 아니며, 앞선 정리에서도 의도적으로 남긴 것이다.

**14px 라벨의 감싸짐 확인** (열 가용 폭 = `w-28` 112 − `pr-4` 16 = 96px):

```
postMessage 경계   ≈124px → 2줄   ← 최장. "postMessage" 한 토큰이 ≈88px로 96px 안에 들어감
v1.5.x 운영 중     ≈146px → 2줄   (NBSP로 "운영 중"이 붙어 v1.5.x / 운영 중으로 갈림)
회귀 없이 완료      ≈100px → 2줄
나머지 8건                 1줄
```

전부 2줄 이내. 다만 `postMessage`는 단일 토큰이 96px에 8px 여유로 들어가는 유일한
경계 항목이다 — 전역 `break-word`를 걷어냈으므로 이보다 긴 라틴 토큰이 라벨에 새로
들어오면 열을 넘는다. 라벨은 열 폭 기준으로 검토할 것.
