# 네이버웹툰 면접 정보 취합 (2026-08-07 웹 검색)

> 공개 후기·공식 채용 콘텐츠에서 취합. 후기는 시기·직군이 제각각이라
> **구조는 교차 확인된 것만 믿고, 세부는 프리 인터뷰에서 직접 확인**한다.
> 사실관계 출처는 문서 끝에.

## 1. 전형 실체 — 후기 교차 확인 결과

| 단계 | 실체 (후기 기준) |
|---|---|
| 서류 | 이력서/포트폴리오. **별도 온라인 코딩테스트 없음** (복수 후기 일치) |
| 프리 인터뷰 | **면접관 1명, 40분.** FE 기초 지식 + 지원서 기반 질문 |
| 실무(기술) 면접 | **1:1 세션 2~3회, 각 1시간.** 후기마다 2세션/3세션으로 갈림. **각 세션에 ~30분 라이브 코딩 포함** |
| 최종 | 신입 후기 기준 HR 30분 + CTO 60분. 인성검사 1시간 별도 |

### ⚠ 준비 방향이 바뀌는 발견

**JD의 "실무 인터뷰(*코딩테스트 포함)"는 별도 온라인 코테가 아니라
면접 중 라이브 코딩일 가능성이 높다.**

- 난이도: "평소 꾸준히 준비했다면 크게 어렵지 않은" 수준 (경력 후기)
- 형태: 화면 공유 + **말하면서 푸는** 방식
- 시사점: 프로그래머스식 온라인 코테 연습만으로는 부족하다.
  **소리 내어 사고 과정을 설명하며 푸는 연습**이 본 준비다.
  문제 난이도 자체는 기초~중급이면 되므로, 로드맵의 "초보자 레벨부터"
  방침과 충돌하지 않는다 — 오히려 유리하다.

## 2. 기술 질문 성격

- **지원서(이력서) 기반이 원칙.** 이력서에 쓴 기술은 전부 질문 후보다.
  → 제출 게이트와 연결: 이력서의 모든 항목은 "내부 동작 + 유사 기술과의 차이"를
  답할 수 있어야 한다. career-claims 근거 등급(구현/리뷰)을 지키는 이유가 하나 더 생겼다.
- **기본기 비중이 높다**: JS(실행 컨텍스트, 이벤트 루프, 호이스팅, 이벤트 전파),
  CSS(애니메이션 성능, 렌더링), 브라우저(스크립트 로딩, CORS), SPA 원리
- **양방향 토론형**: "가장 자신 있는 프로젝트/코드", "겪은 기술적 어려움",
  "요즘 관심 기술"로 토론. 단답 검증이 아니라 함께 파고드는 방식
- 한 인턴 후기의 자기평가: "이건 뭔가요?에 답하는 수준은 아는 게 아니다" —
  깊이 검증이 표준이라는 방증

## 3. 평가 축 — 공식 채용 콘텐츠(개발자 A·B 인터뷰)에서

- **"함께 일하는 사람"을 뽑는다** — 기술 단독이 아니라 협업 신호
- **꾸준한 관심과 성장 태도** — 스터디, 기술 블로그, GitHub 기록을 가산점으로 명시
- **"눈에 보이는 문제만 해결한 것이 아니라 그 이상으로 고민하는 태도"** —
  프로젝트 개수보다 문제 해결 과정과 사고 깊이
- **라이브러리/프레임워크 원리 탐구** 경험을 직접 언급
- 온보딩이 구조화되어 있음(히스토리 문서화, 컨벤션 의사결정 공유) —
  우리 쪽 온보딩 표준화 경험(패밀리케어)과 접점

## 4. 우리 준비에 주는 시사점

1. **라이브 코딩 = 코테 연습의 형태를 바꾼다.** 문제를 푼 뒤 풀이를 소리 내어
   재연하는 단계를 매일 루틴에 넣는다. 기록보다 설명이 본 게임이다.
2. **이력서가 곧 질문지다.** 제출 전에 이력서의 모든 기술 명사 옆에
   "내부 동작 한 단락 + 대안과의 차이 한 문장"을 붙일 수 있는지 자가 점검.
   못 붙이는 항목은 이력서에서 빼는 게 맞다.
3. **"요즘 관심 기술" 질문은 우리에게 유리한 홈그라운드다** — AI 협업 인프라,
   계층형 Claude Code 설정. JD의 AX 강조와도 겹친다. 2분 답변으로 준비.
4. **성장 태도 증빙이 약하다.** 기술 블로그·스터디 기록이 없다면, 포트폴리오
   케이스 스터디 11건이 그 역할을 한다고 명시적으로 말할 수 있어야 한다
   ("문서화한 의사결정 기록"으로 프레이밍).
5. **기본기 복습 목록**(2절 기반): 실행 컨텍스트·이벤트 루프·이벤트 전파,
   렌더링 파이프라인(reflow/repaint — 성능 진단 사례와 연결하면 강함),
   CORS(크로스 코드베이스 postMessage 사례와 연결), SPA vs SSR(포트폴리오로 연결).
   **전부 자기 사례에 연결 가능한 주제들이다 — 개념 암기가 아니라 사례 연결로 준비.**

## 5. 미확인 — 프리 인터뷰에서 물어볼 것

- 실무 면접이 2세션인지 3세션인지 (후기 갈림)
- 라이브 코딩의 언어/환경 (JS 자유인지, 특정 플랫폼인지)
- 캐치 후기에 "사전과제" 언급이 있으나 직군 불명 — FE 경력에도 해당하는지
